1Flow ภาพรวม

📌 ขอบเขตของเอกสารนี้: การเชื่อมต่อ ระบบห้องปฏิบัติการ (LIS) ยี่ห้อ GEMs ของ โรงพยาบาลเมืองสมุทร (ปู่เจ้าฯ + ปากน้ำ) เข้ากับ HA.OS (ระบบ HIS ใหม่ที่ส่งมอบ) · ในเอกสารทั้งฉบับ คำว่า “HIS” = HA.OS · “LIS” = GEMs
งานนี้เป็น interface ที่ต้องยืนยันขอบเขตในช่วง Fit Gap และผูกเข้าแผนพัฒนา — ดู Module Fit Gap และ Checklist

1.3 State Machine — สถานะของรายการตรวจ

New RequestStatus=N→ Accepted TestStatus=A→ Prelim ResultStatus=P→ Final ResultStatus=F
จากสถานะเหตุการณ์ (API / ค่า)ไปสถานะ
—LabRequest · RequestStatus = NNew — LIS สร้างคิวรอรับสิ่งส่งตรวจ
NewLabRequest · RequestStatus = UUpdated (แก้ไขใบสั่ง)
NewLabRequest · RequestStatus = CCancelled (ยกเลิกทั้งใบ)
NewUpdateStatus · TestStatus = AAccepted — รับแลปแล้ว
NewUpdateStatus · TestStatus = JRejected — สิ่งส่งตรวจไม่ผ่าน ต้องเจาะใหม่
AcceptedLabResult* · ResultStatus = PPrelim — ผลเบื้องต้น (ส่งซ้ำได้หลายครั้ง)
PrelimLabResult* · ResultStatus = FFinal — ผลสมบูรณ์ ปิดงาน
FinalUpdateStatus · TestStatus = CRecall — ถอยสถานะเพื่อแก้ผล รอ Approve ใหม่
AcceptedUpdateStatus · TestStatus = XVoided — ยกเลิกรายการตรวจ

1.4 คีย์เชื่อมข้อมูล (Correlation Key)

Keyใช้ในเส้นบทบาท
LabNoทุกเส้น ยกเว้น Token / RequestByVisitNo / Transfusionคีย์หลัก ผูก Order ↔ Status ↔ Result — HIS เป็นผู้ออกเลข
TestCodeLabRequest, UpdateStatus, LabResult ทุกตัวคีย์รอง ระบุรายการตรวจภายในใบเดียวกัน
HNLabRequest, RequestByVisitNo, Transfusionคีย์ผู้ป่วย
BagNoBBCrossmatch, Transfusionคีย์ถุงเลือด
BarcodeNoRequestByVisitNoHN หรือเลขนัดหมาย (input จาก Kiosk)
⚠️ ระวัง: Transfusion/report ไม่มี LabNo — ผูกข้อมูลได้ด้วย HN + BagNo เท่านั้น

2Flow by Case

Case 1 — สั่งตรวจปกติ (Push ทีละใบ)

🏥 HIS🧪 LIS
1
POST /api/LabRequestLabNo, HN, TestList[], RequestStatus = "N"
2
◀ { Status: 0, Message: "Success" }

ใช้เมื่อ: แพทย์สั่งตรวจใน OPD/IPD ทีละใบ → HIS ยิงทันทีที่ Save Order

Case 2 — สั่งตรวจเป็นชุด / Sync คิวจากเครื่อง Computer

🏥 HIS🧪 LIS
1
POST /api/LabRequestQueueRequestList[ {Order1}, {Order2}, … ]
2
◀ { Status: 0, Message: "Success" }

ใช้เมื่อ: ส่งคิวรวมของหน่วยงาน/เครื่อง หรือ Re-sync งานค้าง

⚠️ ข้อจำกัด: โครงสร้างเหมือน LabRequest แต่ ไม่มีฟิลด์ Quantity ⇒ สั่งขอเลือดผ่านเส้นนี้ไม่ได้

Case 3 — Kiosk / จุดเจาะเลือด ดึงรายการด้วย Barcode (Pull)

🧪 LIS / Kiosk🏥 HIS
ผู้ป่วยสแกนบัตร / ใบนัด ที่ Kiosk
1
POST /api/RequestByVisitNo{ BarcodeNo: "0845466" }
2
◀ พบ: { Status: 0, Message: "มีรายการตรวจวันนี้", RequestList: [...] }
3
◀ ไม่พบ: { Status: xx, Message: "ไม่พบ HN" }
LIS แสดงคิว / พิมพ์ Sticker Barcode ให้จุดเจาะเลือด
💡 Message ใช้บอกบริบทเพิ่ม เช่น "มีรายการตรวจวันอื่นด้วย" ⇒ ต้องตกลงชุด Message มาตรฐานร่วมกัน

Case 4 — แก้ไข / ยกเลิกใบสั่งตรวจ (จาก HIS)

กรณีค่าที่ส่งผลลัพธ์
แก้ไขทั้งใบLabNo เดิม + RequestStatus = "U"LIS อัปเดตใบสั่งเดิม
ยกเลิกทั้งใบLabNo เดิม + RequestStatus = "C"LIS ยกเลิกทั้งใบ
ยกเลิกบางรายการRequestStatus = "U" + TestStatus = "C"/"X" เฉพาะรายการนั้นLIS ยกเลิกเฉพาะรายการที่ระบุ
🔴 กฎที่ต้องตกลง: เมื่อ RequestStatus = "U" ต้องส่ง TestList[] ทั้งชุด (Replace) หรือ เฉพาะที่เปลี่ยน (Delta) — สเปคไม่ระบุ ถ้าเข้าใจต่างกันรายการจะหายหรือซ้ำ

Case 5 — รับแลป / Reject สิ่งส่งตรวจ (จาก LIS)

🧪 LIS🏥 HIS
1

2
กรณีสิ่งส่งตรวจไม่ผ่าน → TestStatus = "J"HIS แจ้ง Ward ให้เจาะใหม่

ส่งเป็นระดับ TestCode ⇒ ใบเดียวรับแลปบางรายการและ Reject บางรายการได้

3รายละเอียดเคส — Business Rules & Validation

3.3 กติกาเฉพาะเคส

Case 1–2 · สั่งตรวจ

  • LabNo HIS เป็นผู้ออก ต้อง unique ทั้งระบบ (ตัวอย่าง 11 หลัก 12345600102)
  • ฟิลด์บังคับส่วนหัว: LabNo, HN, PrefixName, FirstName, LastName, DateOfBirth, Sex, VisitType, Priority, RequestDate, RequestByCode, RequestBy, RequestStatus
  • ฟิลด์บังคับใน TestList[]: TestCode, TestName, TestType, CollectionDateTime
  • ต่างชาติไม่มีบัตรประชาชน ⇒ ส่ง PassportNo แทน PersonalID
  • Quantity = จำนวนถุงเลือดที่ขอ — รายการที่ไม่ใช่ขอเลือดให้ส่ง 0 (มีเฉพาะ /api/LabRequest)
  • สั่งชุดตรวจ ⇒ TestType = "P" และ TestCode = ProfileCode

Case 3 · Kiosk

  • Input มีตัวเดียว: BarcodeNo = HN หรือ เลขนัดหมาย ⇒ HIS ต้องรองรับทั้ง 2 แบบในฟิลด์เดียว
  • Response คืน RequestList[] โครงเดียวกับ LabRequest (แต่ ไม่มี Quantity)
  • ต้องนิยาม: คืนเฉพาะ order ของวันนี้ หรือ order ค้างทั้งหมด — สเปคใบ้ไว้ว่าคืนได้ทั้งคู่ผ่าน Message

Case 5 · UpdateStatus

  • ส่งเป็นระดับ TestCode — ใบเดียวรับแลปบางรายการ Reject บางรายการได้
  • UpdateBy, UpdateDateTime บังคับ (ใช้ Audit Trail)

Case 6–8 · Result

  • ส่ง P ได้หลายครั้ง · F = ปิดงาน
  • ค่าวิกฤตต้องมาครบชุด 5 ฟิลด์: CriticalFlag, InformCriticalByCode, InformCriticalBy, InformCriticalTo, InformCriticalDateTime
  • Filedata[] รองรับหลายไฟล์ต่อ 1 LabNo
  • Bacteria: OrganismList[] อยู่ใน TestList[] (ไม่ใช่ใน ResultList) — ตำแหน่งซ้อนต่างจากที่คาด ต้องยืนยัน
  • Bacteria: MedicineValue เก็บทั้งผลและ MIC รวมกัน เช่น "S (MIC:<=2)" ⇒ ถ้า HIS ต้องแยกเก็บ ต้อง parse เอง

Case 10 · Crossmatch — ฟิลด์ที่ต้องมีค่าตาม CommandType

CommandTypeความหมายฟิลด์ที่ต้องมีค่า
APPROVEDจองถุงเลือดCrossmatchResult, CrossmatchBy, CrossmatchDateTime
ISSUEDจ่ายเลือดแล้วIssueBy, IssueDateTime (+ ReceiveBy/ReceiveDateTime เมื่อ Ward รับ)
UNTIEยกเลิกการจองUntieBy, UntieDateTime
CANCEL ISSUEยกเลิกการจ่ายCancelIssueBy, CancelIssueDateTime

SubBagNo เป็น Array — ใช้กรณีรวมถุงเลือด (pooled) · ทุก CommandType ใช้ payload โครงเดียวกัน ต่างกันที่ฟิลด์เวลา/ผู้ทำที่ถูกเติม

Case 11 · Transfusion

  • V/S (Pulse, BloodPressure, Temperature, RespiratoryRate) = วัดหลังหยุดให้เลือด
  • ลายเซ็น 3 ระดับ: ReportBy (พยาบาล) → CertifyBy (แพทย์) → CheckingBy (นักเทคนิคการแพทย์)

4รายละเอียดแต่ละเส้น

สัญลักษณ์: M = Mandatory · O = Option

4.1 POST /api/Token — ขอ Token HIS → LIS

Headers: Content-Type: application/json (ไม่ต้องมี Authorization)

Request Body

FieldTypeM/ODescription
UsernameText(20)Mชื่อผู้ใช้ที่ LIS ออกให้
PasswordText(20)Mรหัสผ่าน

Response Body

FieldTypeDescription
StatusNumber0 = Success, xx = Error
MessageText(250)Success หรือ Error message
TokenText(250)เลข Token สำหรับเรียก API อื่น
ExpireDateTimeอายุของ Token
 
// Request
{ "Username": "Gems", "Password": "1234" }

// Response
{ "Status": 0, "Message": "Success",
  "Token": "xxxxxxxxxxx", "Expire": "31/12/2025 23:59:59" }
💡 ข้อควรทำ: cache Token ไว้ในหน่วยความจำ · ขอใหม่เมื่อเหลืออายุ < 5 นาที หรือเจอ HTTP 401

4.3 POST /api/LabRequestQueue — ส่งใบสั่งตรวจแบบชุด HIS → LIS

โครงสร้าง = LabRequest ครอบด้วย RequestList[]

{
  "RequestList": [
    { "LabNo": "12345600102", "HN": "0845466", /* …ฟิลด์เหมือน LabRequest… */
      "TestList": [ { "TestCode": "CH003", "TestName": "Creatinine",
                      "TestType": "T", "CollectionDateTime": "07/02/2023 11:27:30" } ] },
    { "LabNo": "12345600103", "HN": "0845467", "TestList": [ /* … */ ] }
  ]
}
🔴 ข้อจำกัด: Response ไม่ระบุว่าใบไหนสำเร็จ/ล้มเหลว — batch เป็น all-or-nothing หรือ partial? ต้องตกลง · แนะนำขอเพิ่ม ResultList[{ LabNo, Status, Message }]

5ประเด็นค้าง / ข้อควรตกลงก่อนพัฒนา

5.1 ประเด็นเชิงออกแบบ — ต้องเคลียร์กับ GEMs

#ประเด็นผลกระทบ / สิ่งที่ต้องทำ
1Token ฝั่ง HIS — สเปคมี /api/Token เฉพาะฝั่ง LIS แต่ 7 เส้น LIS→HIS ต้องใช้ BearerHIS ต้องสร้าง Token API เอง หรือใช้ API Key แทน — ต้องตกลง
2Batch Response ไม่ระบุรายใบ — /api/LabRequestQueue คืนแค่ Status/MessagePartial fail ตรวจไม่ได้ → ขอเพิ่ม ResultList[{LabNo, Status, Message}]
3ไม่มีตาราง Error Code — มีแค่ "0 = Success, xx = Error"ต้องขอ Error Code Table ก่อนเขียน error handling
4ทิศทาง Transfusion/report — สเปคว่า LIS→HIS แต่พยาบาลบันทึกที่ HISถ้าผิดทิศ ต้องกลับด้าน = LIS เป็นผู้สร้าง API แทน
5Quantity มีเฉพาะ /api/LabRequestสั่งขอเลือดผ่าน Queue / Kiosk ไม่ได้
6BBScreening ไม่มี ResultStatus และ Filedata[]แนบ PDF ผล Blood Bank / ส่ง Prelim ไม่ได้
7OrganismList[] อยู่ใน TestList[] (ไม่ใช่ใน ResultList[])ถ้า 1 Test มีหลาย Specimen จะแยกไม่ได้ — ต้องยืนยันตำแหน่ง
8RequestStatus="U" = Replace หรือ Delta?ถ้าเข้าใจต่างกัน รายการตรวจจะหาย / ซ้ำ
9Idempotency — ส่ง LabNo ซ้ำด้วย RequestStatus="N" จะเกิดอะไรเสี่ยง Order ซ้ำเมื่อ retry
10ขนาด Payload — Image และ Filebase64 เป็น Base64 ไม่จำกัดขนาดต้องกำหนด Max size + timeout + maxRequestLength ที่ IIS
11Retry / Timeout policy ไม่ระบุต้องตกลง: retry กี่ครั้ง, backoff, dead-letter queue
12MedicineValue รวมผล + MIC ในสตริงเดียว ("S (MIC:<=2)")HIS ต้อง parse เอง ถ้าต้องการแยกเก็บ
13RequestByVisitNo คืน order ช่วงไหนต้องนิยาม: วันนี้ / ค้างทั้งหมด / N วันย้อนหลัง
14ไม่มี API ถามสถานะย้อนกลับ (Query by LabNo)ถ้า Callback หาย ต้องมีทาง reconcile
