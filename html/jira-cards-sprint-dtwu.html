DTWU-S2-03 DTWU Fit Gap M1: เวชระเบียน + เวชสถิติ
Epic: Fit Gap Analysis  ·  Due: 17/Jul/2026
เจ้าของหลัก: ชมพู่ (BA)
สิ่งที่ต้องทำ: ขอบเขตที่ต้องคุย: จัด Workshop ร่วม Process Owner งานเวชระเบียนและเวชสถิติ ทบทวนความต้องการด้านลงทะเบียนผู้ป่วย/กำหนดเลข HN การสแกนบัตรประชาชน ข้อมูล demographic การจัดเก็บ/ค้นคืนแฟ้มเวชระเบียน การลงรหัสวินิจฉัย ICD-10/ICD-9CM และรายงานสถิติผู้ป่วยตามที่กระทรวงสาธารณสุขกำหนด เทียบกับ HA.OS/DTMU แล้วสรุปผลเป็น Fit/Config/Partial/Gap พร้อม Effort และแนวทางดำเนินการ · ขั้นตอนการทำงาน — (1) เตรียมคำถามก่อนไป: ไล่ข้อกำหนดของโมดูลนี้ในเอกสารแนบท้าย TOR ทีละข้อ แปลงเป็นชุดคำถามที่ตอบได้ว่า “ทำได้เลย / ต้องตั้งค่า / ต้องพัฒนาเพิ่ม / ไม่ต้องใช้” · เตรียมหน้าจอ HA.OS ที่จะใช้ demo ประกอบคำถามแต่ละข้อ · อ่านผล Fit Gap ของ DTMU และของอีกไซต์ในโมดูลเดียวกันก่อน จะได้ไม่ถามซ้ำและเห็นจุดที่ต่างกัน · ส่ง Agenda + ชุดคำถาม + รายชื่อผู้ที่ต้องเข้าร่วม (Process Owner และผู้ปฏิบัติงานจริง) ให้โรงพยาบาลล่วงหน้าอย่างน้อย 3 วันทำการ · (2) ไป Fit Gap หน้างาน: เดินดูการทำงานจริงที่จุดบริการก่อนเข้าห้องประชุม ดูว่าใครทำอะไร ใช้ฟอร์มอะไร ต่อกับใคร · ไล่คำถามทีละข้อพร้อม demo หน้าจอจริงให้ผู้ใช้เห็นภาพก่อนตอบ · บันทึกคำตอบรายข้อพร้อมชื่อผู้ให้ข้อมูล · เก็บตัวอย่างฟอร์ม/รายงานที่ใช้จริงและถ่ายรูปหน้างานไว้อ้างอิง · ข้อที่ตอบไม่ได้ในห้องให้บันทึกเป็นประเด็นค้าง (Parking Lot) พร้อมผู้รับผิดชอบและวันที่ต้องตอบกลับ · (3) กลับมาสรุป: ลงผล Fit / Config / Partial / Gap รายข้อในเอกสาร Fit Gap พร้อมประมาณการ Effort · แยกข้อที่เป็น Gap ว่าปิดด้วย Config หรือต้อง Develop และกระทบโมดูลอื่นหรือไม่ · สรุปประเด็นค้างทั้งหมดพร้อมเจ้าภาพและวันครบกำหนด · ส่งสรุปให้ Process Owner ยืนยันภายใน 3 วันทำการหลังประชุม · อัปเดต Fit Gap Tracker และตาราง Module Fit Gap ให้สถานะตรงกับความจริง · (4) ยืนยันร่วม DTMU และปิดรอบ: นำผลเข้ารอบ ② สรุป Fit Gap ร่วม PO มีน (DTMU) เพื่อยืนยันว่าทำได้บนฐานระบบเดิม ระบุผู้ตัดสินใจของโมดูล และปิดประเด็นค้างให้หมด ก่อนส่งต่อให้ทีมจัดทำ Flow AS-IS/TO-BE และเอกสาร BR/FR
ผลลัพธ์ที่ต้องได้ (DoD): Fit/Config/Partial/Gap + ประเด็นค้างมีเจ้าภาพและกำหนดปิด + Process Owner ยืนยันผลแล้ว + Fit Gap Tracker อัปเดต
ผู้เกี่ยวข้อง: สาม, มีน, จูน

DTWU-BRF-04 DTWU BR/FR: M4 คลินิกทันตกรรม
Epic: Fit Gap Analysis  ·  Due: 28/Aug/2026
เจ้าของหลัก: จูน (PO)
สิ่งที่ต้องทำ: จัดทำเอกสารความต้องการของ M4 คลินิกทันตกรรม ต่อยอดจากผล Fit Gap รอบ S4 และ Flow AS-IS/TO-BE ที่ BA ชมพู่ จัดทำไว้ แบ่งเป็น 2 ส่วนในฉบับเดียวกัน · (1) BR — Business Requirement: วัตถุประสงค์ทางธุรกิจของโมดูล ปัญหาที่ต้องแก้จากงานปัจจุบัน ผู้มีส่วนได้ส่วนเสียและเจ้าของกระบวนการ กฎ/ระเบียบ/นโยบายของโรงพยาบาลและหน่วยงานภายนอกที่ต้องปฏิบัติตาม ตัวชี้วัดที่ใช้วัดผลหลังใช้ระบบ และข้อจำกัด/สมมติฐานที่ตกลงกันไว้ · (2) FR — Functional Requirement: แตกเป็นข้อย่อยรายฟังก์ชัน ระบุ Input → Process → Output ของแต่ละข้อ กฎการตรวจสอบข้อมูล (Validation / Business Rule) บทบาทและสิทธิ์ที่ใช้ฟังก์ชันนั้นได้ รายงาน/แบบฟอร์มที่ต้องออก จุดเชื่อมต่อกับโมดูลอื่นและระบบภายนอก รวมถึงข้อกำหนดที่ไม่ใช่ฟังก์ชันที่เกี่ยวข้อง (ปริมาณข้อมูล เวลาตอบสนอง การเก็บ Audit Log) · (3) เกณฑ์ผ่าน (Acceptance Criteria) รายข้อ: ทุกข้อ FR ต้องมีเกณฑ์ที่วัดได้ชัดเจน ไม่ใช่ความเห็น เขียนให้เจ้าหน้าที่หน้างานอ่านแล้วตรวจเองได้ ใช้เป็นตัวตั้งต้นเขียน Test Case SIT/UAT และเป็นเกณฑ์ตัดสินตอน UAT ต่อไป · ปิดท้ายด้วย ตาราง Traceability (RTM) ผูกทุกข้อกลับไปที่ข้อ Fit Gap ข้อกำหนดใน TOR และขั้นตอนใน TO-BE Flow เพื่อพิสูจน์ว่าไม่มีข้อไหนตกหล่นและไม่มีข้อไหนเกินขอบเขต · ให้ มีน + ก้อง ร่วมทบทวน และยืนยันว่าทำได้บนฐาน DTMU/HA.OS ก่อนนำเข้ารอบนำเสนอ User เพื่อลงนามยืนยันความต้องการ · เอกสารฉบับนี้คือ ผลงานส่งมอบงวด 2 ข้อ 2 ตาม TOR (เอกสารวิเคราะห์และปรับปรุงความต้องการของผู้ใช้งานระบบ)
ผลลัพธ์ที่ต้องได้ (DoD): เอกสาร BR/FR รายโมดูล (BR + FR + เกณฑ์ผ่านรายข้อ) + ตาราง Traceability (TOR ↔ Fit Gap ↔ BR ↔ FR ↔ TO-BE Flow) ผ่านการทบทวนของ SA และ PO มีน
ผู้เกี่ยวข้อง: ชมพู่, มีน, ก้อง
